# Native File Operation Job Protocol

## Purpose

Phase 15 establishes a single event contract between the Android native operation engine and the TypeScript operation center. The Capacitor plugin is only the transport adapter; byte-level work remains in `NativeFileOperationService`.

## Operation identity

Every long-running native operation receives the same `operationId` generated by the application operation engine. That ID is echoed in every event and control request.

## Events

### `fileOperationState`

```json
{
  "operationId": "op-42",
  "type": "copy",
  "status": "running|paused|cancelling|completed|failed|cancelled",
  "message": "optional"
}
```

### `fileOperationProgress`

```json
{
  "operationId": "op-42",
  "type": "copy",
  "bytesProcessed": 5242880,
  "totalBytes": 10485760,
  "fraction": 0.5,
  "currentPath": "/storage/.../file.bin"
}
```

### `fileOperationError`

Contains the same identity plus a human-readable `message`.

## Controls

The plugin exposes: `cancelFileOperation`, `pauseFileOperation`, `resumeFileOperation`, and `getFileOperationStatus`. Controls are cooperative and safe: cancellation is observed at stream/chunk boundaries, and pause is observed between read/write chunks.

## Provider coverage

The protocol is already wired into native Local-file and SAF copy/move paths. Cross-provider move follows copy-then-delete and only deletes the source after the destination copy completes successfully.

## Important lifecycle rule

Native Player/Storage/File Operation objects are never sent through the JS bridge. Only IDs, metadata, progress, and state events cross the bridge. This keeps large payloads out of the WebView heap.
